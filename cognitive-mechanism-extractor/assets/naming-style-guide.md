# 机制命名风格指南

> 命名是 Skill 最容易失真的环节。这份指南是命名阶段的**强制规则**,不是建议。

## 1. 命名公式

`[认知动作] + [情境/约束] + [价值方向] + "机制"`

可以省略其中之一,但 3 项必须保留 2 项。

**例**:
| 公式落实 | 例 |
|---|---|
| 认知动作 + 情境 + 价值方向 | "高模糊需求下的结构化澄清机制" |
| 认知动作 + 情境 | "跨部门阻力中的最小共识推进机制" |
| 认知动作 + 价值方向 | "弱信号拼接与前摄干预机制" |
| 情境 + 认知动作 | "多约束条件下的优先级折中机制" |

## 2. 严禁清单

| 类别 | 严禁词 | 严禁原因 |
|---|---|---|
| 人格类型词 | INTJ / INFP / 红色性格 / 九型 X 号 | 一次访谈无法稳定推断人格 |
| 临床/心理词 | 完美主义倾向 / 强迫倾向 / 焦虑型 / 创伤后 | 越界,缺乏专业资质 |
| 空洞赞美词 | 有 owner 意识 / 责任心强 / 综合素质强 / 善于沟通 | 不可证伪,无法做 transfer 测试 |
| 招聘话术 | 高潜 / Top 10% / 业界顶尖 / 万里挑一 | 招聘判定越界 |
| IQ/认知能力词 | 智力超群 / 学习能力极强 / 天赋型选手 | 越界推断 |
| 命运词 | 天生的领导者 / 注定的工程师 | 把暂时模式误为命运 |

## 3. 推荐认知动作动词库

(便于命名时挑选)

- **信号读取类**: 识别、拼接、过滤、放大、捕捉、读取、辨识、追踪
- **拆解类**: 拆解、还原、分层、拆题、解构、提炼、抽象
- **权衡类**: 折中、平衡、取舍、择优、规避、保守、激进
- **校准类**: 校准、对齐、调焦、订正、回归、修正
- **推进类**: 推进、串联、对接、贯穿、落地、收敛
- **反思类**: 复盘、抽象、归因、提纲、沉淀

## 4. 推荐情境关键词库

(命名时显示机制适用的边界)

- **模糊/确定性**: 高模糊需求、目标不清、约束分散、规则未定 / 边界清晰、强 SLA、硬时限
- **资源/权威**: 跨部门无权威、资源受限 / 资源充足、自有权限
- **风险/可逆**: 不可逆决策、高代价试错 / 可快速回滚、低成本试错
- **协作/孤立**: 多方共建、远程异步 / 个人攻坚、同步密集
- **新旧**: 0 到 1 落地 / 老系统重构 / 大促支撑 / 长尾运维

## 5. 推荐价值方向词库

- 降低返工 / 降低回滚成本 / 提升收敛速度 / 提升共识效率 / 降低误判率 / 提升复用度 / 降低耦合 / 提升可观察性 / 降低决策摩擦

## 6. 命名校准对话脚本

进入命名阶段时,AI 必须按以下顺序与候选人确认:

**步骤 1: 给出 2-3 个候选名**

> "基于我们刚才聊的 3 个事件,我想到 3 个候选名,你可以挑、改、推翻。
> A. [名称 A]
> B. [名称 B]
> C. [名称 C]
> 你更认哪一个?或者你想换成什么?"

**步骤 2: 反事实测试**

> "如果你的工作方式里**没有**这条机制,你在最近这个事件里会做出什么不同的判断?"

候选人答不上来 → 这个机制不成立,回到 [prompts/incident-deep-dive.md](../prompts/incident-deep-dive.md) 补证据。
候选人能立刻举出反例 → 机制可信度高。

**步骤 3: 复述确认**

> "用你自己的话,把这条机制讲给一个完全没听过你工作的同行听,你会怎么说?"

候选人复述与 AI 命名差异 < 30% → 采纳。
差异 > 30% → **以候选人版本为准**,不强推 AI 命名。

## 7. 常见反模式与改写

| 错误命名 | 问题 | 改写 |
|---|---|---|
| "高度负责机制" | 空洞赞美,不可证伪 | "高代价决策前的回滚路径前置机制" |
| "复盘能力" | 不是动作机制,是名词性能力词 | "事故复盘中从单点错误抽象到 SOP 的迭代机制" |
| "INTJ 思维" | 人格词,越界 | "新需求评估时的'兼容—故障—回滚'三角清单机制" |
| "全局观" | 太宽,无法 transfer 测试 | "系统底层变更时的上游依赖与下游用户双向追问机制" |
| "技术全局考虑周到" | 简历术语,不是认知机制 | "技术选型前的'三档失败回滚难度'分级机制" |

## 8. 自检 4 问

每次完成命名,AI 在内部确认:

1. 这个名字里有没有"如何思考/判断/推进"的动作?
2. 这个名字里有没有指出适用场景?
3. 这个名字里有没有可以反事实测试的内容?
4. 候选人复述这个名字时,会不会卡壳?

任何一项答案不利,回去重命名。
