# 面试表达模板

> 三种长度、三种压力情境的回答骨架。每条都必须基于已验证机制(validated)或有力假设(strong-hypothesis),不允许只用弱信号撑场。

## 1. 自我介绍可嵌入版本(60 秒)

**骨架**:
1. 一句身份锚点(角色 + 年限 + 主战场)
2. 一句"我最稳定起作用的一种工作方式":[机制 M-001 的一句话定义]
3. 一句代表性场景(回指一个 evidence card)
4. 一句"我目前在做什么/想做什么"

**例(虚构)**:
> "我做 macOS 桌面端架构差不多 7 年。我最稳定起作用的方式,是在系统底层能力变更时,先把'兼容点—故障模式—回滚路径'三件事钉住,再设计上层接口。比如我曾在 ESF 接入时,先用 3 周搭出灰度回滚链路,再放主功能上线。我现在在做企业级 EDR/DLP 的多进程隔离架构。"

## 2. STAR 叙事版本(选 1-2 个核心事件,2-3 分钟)

**骨架**:
| STAR | 对应证据卡字段 |
|---|---|
| Situation | `context` + `trigger_moment` |
| Task | `task_or_problem` |
| Action | `considered_options` + `decision_rule` + `action_taken` |
| Result | `outcome`(若候选人有量化才用,否则定性) |

**关键**: Action 段要讲出"为什么不选另一个方案",这是机制最容易显形的地方。

**例(虚构)**:
> "[Situation] 当时我们做企业 SASE 的 EDLP 从 0 到 1 落地,要在 7 个月里覆盖 USB、AirDrop、手机、外发审计等通道。
> [Task] 难的是 Apple 的 SystemExtension 当时刚替代 Kext,文档不完整,而且 Endpoint Security 和 NetworkExtension 在权限模型上有冲突。
> [Action] 我做的第一件事不是选技术栈,而是先把 7 个通道按'失败回滚难度'分了 3 档,把回滚最难的 USB 和 AirDrop 放到最后两个迭代,先攻外发审计这条最可控的链路。
> [Result] 最后 EDLP 6 个月上线,外设管控滞后了两周但没出回滚事故。"

## 3. 高压追问下的简洁版本(20-40 秒)

适合面试官问"那你做这个项目最大的难点是什么"、"为什么不选 X"、"你怎么决定的"。

**骨架**: [情境一句] + [关键判断一句] + [结果一句],不超过 3 句。

**例(虚构)**:
> "ESF 在多进程隔离上有冷启动延迟问题,我们当时面临要不要按官方建议拆 4 个 SystemExtension。我没拆,因为我们的 SOP 是先拿一个最小可工作版本测真实场景再决定。最后只拆了 2 个,延迟问题消失,代码复杂度也没爆炸。"

## 4. 面试中要避免的误表述

| 类型 | 避免说 | 改成 |
|---|---|---|
| 标签化自我 | "我比较有 owner 意识" | "我在做架构决策时,会先把回滚路径搭出来再放主功能" |
| 假量化 | "我们提升了 50%(候选人未说过)" | "我们显著缩短了启动时间,但具体数字我手上没有了" |
| 包揽功劳 | "我一个人做完了 X" | "在团队 _ 人的协作下,我负责 X 部分,核心判断包括 ..." |
| 空泛形容词 | "技术全局考虑周到" | "在做技术选型时,我会先把'兼容点—故障模式—回滚路径'写成清单再决策" |
| 越界推断 | "因为我是 INTJ 所以喜欢架构" | "做架构这件事跟我习惯先想清边界再动手有关" |

## 5. 自检清单

- [ ] 我引用的事件,候选人在访谈里亲口讲过吗?
- [ ] 我有没有添加候选人没说过的数字?
- [ ] 这段表达能回指到具体机制吗?
- [ ] 这段表达暴露了"为什么这样判断",而不只是"做了什么"吗?
- [ ] 候选人愿意在压力下重复这段话吗(测试可复述性)?

## 6. 候选人共创

最终版本要让候选人**亲口复述一遍**。如果候选人复述时:
- 改了 1-2 个词 → 采纳候选人版本
- 完全卡壳或大改 → 这条不放入最终报告,回到 [prompts/naming-and-validation.md](../prompts/naming-and-validation.md) 重做
