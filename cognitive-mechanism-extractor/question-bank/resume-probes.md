# 简历破题问题库 (resume-probes)

> 用于阶段 2(简历假设图)。目标: 用简历做"假设入口",不做"结论出口"。

## 1. 高优先问题(每个候选人都要问 1-2 个)

| 编号 | 问题 | 期望萃取的对象 |
|---|---|---|
| RP-01 | "你这份简历里,哪一段经历最容易被人低估,但其实最能代表你?" | 高价值样本优先级 |
| RP-02 | "如果只能让我读简历里的一段,你希望我读哪段?为什么?" | 候选人的自我聚焦 |
| RP-03 | "简历里有没有哪句话现在看你会改?为什么?" | 候选人的反思力 |
| RP-04 | "这份简历里,最不像你的一句话是哪句?" | 与岗位话术的差距 |

## 2. 职责反差类(发现非典型实践)

| 编号 | 问题 | 萃取对象 |
|---|---|---|
| RP-05 | "[某段经历]里,最不像你岗位说明书的一件事是什么?" | 非正式实践 |
| RP-06 | "你做了什么不是 KPI 但当时非做不可的事?" | 自驱判断 |
| RP-07 | "你做过什么没人要求但你坚持做完的事?" | 隐性 ownership |
| RP-08 | "你做过什么你的同事不会这样做的事?" | 独特认知差异 |

## 3. 转折类(发现风格变化)

| 编号 | 问题 | 萃取对象 |
|---|---|---|
| RP-09 | "你从 [上一段] 跳到 [这一段] 的时候,最难适应的是什么?" | 跨领域学习模式 |
| RP-10 | "从 [游戏服务端 → iOS → macOS 安全] 跨度这么大,你是怎么入门新领域的?给我一个进入新领域第 3 个月内的具体判断。" | 元学习机制 |
| RP-11 | "如果时间倒回到 [某个跳跃点],你做的最关键的一个动作是什么?" | 决策习惯 |

## 4. 缺口类(发现未说清的部分)

| 编号 | 问题 | 萃取对象 |
|---|---|---|
| RP-12 | "你简历里写 '完成 X 0→1 落地'。0→1 听起来很容易但其实有几个'最难的瞬间'。你愿意挑 1 个讲给我听吗?" | 决策点定位 |
| RP-13 | "[某段经历]里,你简历没写的失败/坑/返工是什么?" | 反思机制 |
| RP-14 | "你简历写 '负责架构设计'。具体来说,你最近一次做架构判断,是在什么场景?" | 真实判断而非职责 |

## 5. 自评类(挖出空话背后的事件)

| 编号 | 问题 | 萃取对象 |
|---|---|---|
| RP-15 | "你简历里写 '___'(自评词)。给我一个**最近**的事件,这条评价在那件事里是怎么体现的?" | 把自评转回事件 |
| RP-16 | "'活好,活细,Bug 少' 听起来很有自信。请给我一个'活细'救了你或团队一次的事件。" | 把空话锚定到具体 |
| RP-17 | "'技术全局考虑周到' 是个抽象描述。给我一个你考虑了别人都没考虑的细节,结果被证明是对的事件。" | 同上 |

## 6. 假设生成模板(AI 内部填写)

针对一个虚构候选人(20+ 年 Apple 端架构经验,横跨游戏服务端 → 电商 iOS → 企业安全 macOS)的示例假设:

```
H-001
看起来候选人在 [长周期、深耦合、系统级框架变化大] 的场景里反复完成 [从 0 到 1 的端侧能力落地],
可能存在一种 [在文档不全/接口不稳定的新框架上构建稳定生产服务] 的机制。

需要事件验证:
- 近期 ESF 接入项目中的一个决策瞬间
- 中后期 PacketTunnel 在 SASE 厂商搭建中一个回滚相关决策
- 中期某个 UEM 产品 0→1 的边界判断

status: untested
```

```
H-002
看起来候选人横跨 [游戏服务端 → 电商 iOS → 企业安全 macOS] 这三种业务/技术领域,
可能存在一种 [在新领域里 1-3 个月内识别成败变量] 的元学习机制。

需要事件验证:
- 从游戏服务端转 iOS 客户端的前 3 个月做了哪些 "我以前不会做" 的事
- 从电商直播转企业安全的前 3 个月有什么调整

status: untested
```

```
H-003
简历自评 "活好,活细,Bug 少" 是一句没有事件锚点的空话,
可能存在一种 [在底层开发中做边界保护与防御性设计] 的稳定机制。

需要事件验证:
- 一次因 "活细" 而避免事故的事件
- 一次因 "活细" 反而拖慢进度的事件(必要的反证)

status: untested
```

## 7. 输出格式(给候选人的)

呈现假设地图时,**不超过 5-8 个**,以编号列表 + status 标签呈现。每个假设附 1-2 行"需要怎么验证"。
