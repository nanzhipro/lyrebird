# 萃取方法学操作要点(按需加载)

> 这份文档把 CTA / CDM / CIT / Knowledge Audit / Recent Case Walkthrough 的操作要点压缩成可执行步骤。
> 不是教程,是 cheat sheet。

## 1. Critical Incident Technique (Flanagan, 1954)

### 核心定义
**Critical incident**: 对结果有明显正向或负向影响的具体行为片段。

### 5 个程序步骤
1. **确定目标活动**: 哪类工作 / 哪类决策
2. **设定方法标准**: 准入标准、收集渠道
3. **收集事件**: 通过访谈、自报、观察等收集
4. **分析事件**: 归纳、分类、提取模式
5. **解释与报告**: 把模式转成可教 / 可评估的描述

### 对本 Skill 的映射

| Flanagan 步骤 | Skill 阶段 |
|---|---|
| 1. 确定目标 | 阶段 1: 协作契约确定萃取范围 |
| 2. 设定标准 | 阶段 1: 候选人投入度门槛 + 阶段 2: 假设地图 |
| 3. 收集事件 | 阶段 3: 关键事件深描 |
| 4. 分析事件 | 阶段 4: 跨事件归并 |
| 5. 解释与报告 | 阶段 5/6: 命名与报告 |

## 2. Critical Decision Method (Klein, 1989+)

### 4-Sweep 结构

CDM 标准的访谈结构是 4 个回合(sweep),每个回合关注一类问题:

| Sweep | 焦点 | 关键 probe |
|---|---|---|
| 1. Account | 让受访者完整讲一次 | "请讲一遍这件事" |
| 2. Timeline | 建立时间线 | "T0 是什么? T1?" |
| 3. Deepen | 在关键决策点用 cue/option/goal probe | 详见 [critical-incident-probes.md](../question-bank/critical-incident-probes.md) |
| 4. What-if | 假设性变化测试 | "如果信号晚 2 天..." |

### CDM 的 7 大 probe(详见问题库)

- Cue probe(线索)
- Knowledge probe(知识)
- Goal probe(目标)
- Option probe(备选)
- Experience probe(经验)
- Analogy probe(类比)
- Hypothetical probe(假设)

## 3. Recent Case Walkthrough

### 适用场景
**第一次见候选人时,作为 CDM 的"轻量化开场"**。目的不是深挖,是建立 rapport + 让候选人进入"具体讲事件"的模式。

### 5 个 step

1. 让候选人挑一个最近的具体事件(不超过 6 个月内)。
2. 让候选人按时间顺序讲一遍。
3. 共建时间线(AI 整理后回返候选人确认)。
4. 在时间线里标 2-3 个关键节点。
5. 不要在第一轮深挖,留到 CDM 主体回合。

### 对本 Skill 的映射

阶段 3 的微循环 A 就是 Recent Case Walkthrough。

## 4. Knowledge Audit

### 适用场景
**深描已经做完,需要拔高到"判断风格"层面**。在事件深描的收尾阶段使用。

### 6 类问题(每个事件用 2-3 个)

| 类型 | 焦点 | 例 |
|---|---|---|
| **Past and future** | 大图景 | "你心里一直在守的总目标是什么?" |
| **Big picture** | 全局视角 | "你最怕失去控制的关键变量?" |
| **Noticing** | 觉察 | "你注意到了别人没注意到的什么?" |
| **Job smarts** | 经验捷径 | "你后来形成了什么'不用重想'的判断窍门?" |
| **Opportunities/Improvising** | 即兴判断 | "什么时候你必须 improvise ?" |
| **Self-monitoring** | 自我监控 | "你怎么知道你的判断是对的?" |

### 对本 Skill 的映射

阶段 3 的微循环 C 就是 Knowledge Audit。

## 5. CTA 三阶段(Cognitive Task Analysis)

| 阶段 | 名称 | 任务 | 本 Skill 对应 |
|---|---|---|---|
| 1 | Knowledge Elicitation | 通过访谈、观察、思考有声 (think-aloud) 收集认知数据 | 阶段 1-3 |
| 2 | Data Analysis | 归纳模式、构建知识表征 | 阶段 4 |
| 3 | Knowledge Representation | 把知识表征成图、模型、训练材料 | 阶段 5-6 |

## 6. 文字场景的特殊调整

CTA/CDM 原本是面对面访谈方法,文字场景要做以下调整:

| 原方法假设 | 文字场景调整 |
|---|---|
| 可以看到面部表情、肢体 | 用"短段落 + 分行时间线"补偿 |
| 可以即时打断 | 提前告知"我会经常打断,你别介意" |
| 可以多线追问 | 严格"一次一个 probe" |
| 单次 60-90 分钟搞定 | 拆 2-4 轮,每轮 20-30 分钟 |
| 录音事后转写 | 候选人当场看到 AI 的整理 |
| 受访者可以临时澄清 | AI 必须主动给候选人 "你可以否决任何转述" 的退出口 |

## 7. 与 STAR 法则的关系与差异

| STAR | CDM/CIT |
|---|---|
| 用途: 面试自述模板 | 用途: 默会知识萃取 |
| 颗粒度: 项目级 | 颗粒度: 决策点级 |
| 关注: 结果与个人贡献 | 关注: 信号识别 + 判断依据 + 权衡 + 反证 |
| 偏好: 凯旋型故事 | 偏好: 真实复杂事件 |

**本 Skill 立场**: STAR 是最终面试表达的一种格式(报告阶段 9),不是核心萃取方法。萃取阶段不要用 STAR,要用 CDM。

## 8. 常见操作错误

| 错误 | 修正 |
|---|---|
| 一开口问"你最大的优势" | 改为 "讲一个最近的具体事件" |
| 用人格测试式问题 | 用 CDM cue/option probe |
| 听完一个事件就命名 | 等 ≥ 2 个事件后再做跨事件归并 |
| 不做迁移测试 | 强制 [transfer-probes.md](../question-bank/transfer-probes.md) |
| 不做反证 | 强制 [contradiction-probes.md](../question-bank/contradiction-probes.md) |
| 单方面命名 | 强制候选人复述与改名 |
| 听到漂亮话就采纳 | 把候选人自评还原到事件 |
